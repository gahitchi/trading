## Reproducible findings against G036

- **F1 [blocking]** Existing DB with lost authoritative snapshot and missing
  `ledger.json` can cold-start as a fresh account. Repro: create
  `ExecutionStore(path)`, save account + an applied execution, delete
  `snapshot` with SQLite and unlink `ledger.json`. Reopen; G036 loads
  `None` despite surviving history. The new guard refuses.
- **F2 [blocking]** G036 snapshot-less SQLite with archived fill rows and
  a forged unbound legacy `ledger.json` can re-import the legacy
  monetary state. Repro: save a fill and $900 cash, erase only snapshot,
  overwrite JSON with `{"cash":1000}`. G037 refuses re-import over
  surviving execution history.
- **F3 [blocking]** `json.loads` on authoritative SQLite monetary data
  accepts duplicate keys and nonstandard `NaN`/overflow floats.
  Repro: `UPDATE snapshot SET value='{"cash":900,"cash":1000,...}'`;
  before G037 the duplicate silently wins and can pass ledger validation.
  New `decode` rejects duplicate/nonfinite JSON before semantic checks.
- **F4 [blocking]** Reading archived execution IDs could accept
  `history.coid` differing from the JSON `[receipt_ns, order_id]`
  for that trade ID; explicit export would present contradictory
  attribution. G037 validates column/payload agreement.

## Evidence and compatibility

G037 covers lost diagnostic projections with surviving authoritative
snapshots, interrupted legacy imports, duplicate JSON keys, nonfinite
and overflow floats, broken indexed attribution, and preserved
unmodified legacy migrations. It does not modify broker routing,
strategy signals, fills, capital limits, or authority.

**Known residual blocker:** absent authenticated first-import intent,
an empty SQLite DB with no snapshot and a forged unbound JSON file
cannot be distinguished from a genuinely interrupted first-time legacy
migration. The ADR flags this explicitly. Do not qualify this recovery
path for externally routed paper trading until that distinction is
proved durably.
