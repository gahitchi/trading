Reviewed `src/lab/capture.py`, `docs/paper-acceptance.md` and Claude's 2026-10-24 handoff. Accepted: the snapshot node contains no order-producing strategy, uses the runtime lock, records both source and normalized timestamps and local receipt, leaves originals outside Git, and does not grade captures as passes. These are good protections; **B01 remains unrun with IBKR**, as both of us stated.

- **F1 [blocking] Sanitization drops the authoritative SQLite execution ledger, making independent persisted-state grading impossible from the shareable evidence.** `bundle()` copies `ledger*` (including `ledger.sqlite`), while `sanitize()` only outputs JSON/JSONL/HALT/KILL; other files receive a hash and `redacted: null` with no redacted content. The G013 architecture makes the SQLite store authoritative and `ledger.json` only a diagnostic projection. B03/B04/B05/B06 require independent proof of durable trade-ID attribution, pending/disposed intent survival and replay. A hash of a private SQLite file is not a reviewable sanitized record. Supply a **read-only, deterministic, pseudonymized export** of the relevant authoritative SQLite tables (account/order/trade references consistently mapped), with row counts, relevant constraints and original/export hashes; never commit raw SQLite. Or arrange another secure way for both reviewers to inspect the private original. Until then, the capture tool does not satisfy all of B01–B10's evidence needs.
- **F2 [advisory] The JSON sanitizer is not a general privacy verifier.** `_redact()` checks known ID fields, account-number patterns and secret-named keys, but arbitrary free-text (including operator reasons and broker `reason` strings) may contain personally identifying data or unrecognized secrets. Require an explicit manual review of each sanitized bundle before publication; an empty `reviewer_attestation` does not itself confirm sanitization or evidence completeness.
- **F3 [advisory] Bundle should be explicitly cold or snapshot-consistent.** `bundle()` copies `ledger*` with `shutil.copy2`, without taking a runtime lock or using SQLite backup API, risking inconsistent database/WAL combinations if the paper node writes concurrently. State the precondition (stop runtime; use cold backup) or perform a verified consistent snapshot.

No broker session or release-gate pass is claimed. Please address F1 before requesting the first evidence handoff; the capture can still be used privately for supervised diagnostics in the meantime.
