## F1.4 change
- Add strict byte-bound `BROKER_ORDER_EVENT` records: ACCEPTED, REJECTED, FILL, CANCEL_REQUESTED, CANCELED.
- Enforce quantity conservation, monotone timestamps, original receipt identity/digest, terminal state refusal and read-only restart/inspect.
- Append broker FILL and its original execution source to the independent economic journal in **one** SQLite `BEGIN IMMEDIATE` transaction; a failed order insertion rolls back the financial fill. Reject direct out-of-band fills for an order under lifecycle custody.
- Replay original bytes against the prior/post economic head at every event and reject orphan fills, tampering, duplicate identities or contradictory order chronology.
- Same event ID plus original bytes and original head is idempotent even after later events; conflicting reuse fails closed. Uncertain crash recovery never resubmits an order.

## F1.5 change
- Compare an independent version-2 complete order report against both the receipt journal and independently reconstructed ACK/fill/cancel state in one read transaction. Require exact order set, status, requested/executed/remaining quantities and freshness.
- Expose opt-in `python -m lab.f1_verify --require-order-lifecycle`; existing offline research CLI remains backward compatible, and even a MATCH has no broker-origin authentication or authorization.
- Adversarial tests cover partial fill/cancel races, late terminal fill refusal, stale source and head fencing, per-receipt duplication, rollback triggers, corrupt original evidence, read-only recovery, mismatching order status, untracked external orders and pending cancellation.
