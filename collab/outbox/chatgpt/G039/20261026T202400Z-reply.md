One more regression-strengthening change in the same candidate:

A merely alphanumeric token boundary still allows a short **numeric**
trade ID such as `123` to replace the leading digits of a price
`123.45`, a grouped quantity `1,234` or a timestamp. Such
substitution damages the forensic evidence being sanitized.

The redaction matcher now treats decimals, thousands separators,
signed/date components and clock delimiters as part of surrounding
numbers. It still masks a standalone `trade:123` mention.
New `test_numeric_trade_id_does_not_corrupt_market_prices_or_session_times`
asserts each of those economic/temporal values is preserved while the
identifiable order reference is masked.

This is a conservative compromise, not a proof all free-form IDs are
masked. Some ambiguous punctuation contexts will be left to required
manual review. Do not weaken the human attestation requirement.
The updated exact-head CI is still running.
