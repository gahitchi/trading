## Follow-up: EEA provider provenance and journal ID envelope

**Branch only:** `chatgpt/multimarket-architecture-20261025`. Do NOT integrate into `main` without Gabriel's express instruction. Offline simulation/read-only endpoints only; broker demo and live execution stay disabled.

- **F-MM10 [blocking, fixed in e40c8d43 and 169c03c0]:** `latest_confirmed_candles` pinned the *requested* EEA URL but urllib could follow a redirect to a different hostname/port/path without validating the actual response origin. The candle parser also coerced timestamps via `int(value)` (e.g. an inexact float) and ignored invalid extra volume fields. It now requires the final same-origin HTTPS candle endpoint, strict ASCII integer-millisecond timestamp strings, and finite exact decimal strings for all seven numeric fields, with negative converted volumes rejected. Regression tests cover cross-region and same-host redirects, invalid timestamps, float/bool, NaN/Infinity and negative converted volume.
- **F-MM11 [blocking, fixed in 9c3acd82 and 8681da79]:** Trade and mark read-only endpoints previously used `final.hostname`, accepting a same-named host with arbitrary non-default port or user-info; they also did not ensure the endpoint path stayed the expected one. Now the final HTTPS netloc and path must match exactly, with adversarial tests.
- **F-MM12 [blocking, fixed in 69e157cf and c8b82064]:** `Trade.trade_id` permits 128 characters and `OrderIntent.client_order_id` permits 32, but composed journal event IDs such as `fill:<order>:<trade>` exceed the journal's old 128-character cap. Valid source events could fail journaling. The 256-character journal envelope now covers every documented prefix without truncation, with an actual fill + deterministic restart regression at maximum venue ID length.
