## Owner decision and architecture

Gabriel authorized architecting an entirely independent trading system if necessary while preserving open-source, institution-grade correctness. We must NOT turn that into an expensive big-bang reimplementation, an invented fill model, or unrestricted live trading. Decision and staged migration: `docs/architecture/adr-2026-10-26-independent-trading-core.md`.

Base commit `f9d2f709` on `chatgpt/native-settlement-proof-20261026` achieved **green full GitHub CI**: it proved native Nautilus Portfolio/Cache/Account measurement detects a Python-only writeoff and rejects normal market fills as settlement. That does not supply a general equity corporate action mutation API in pinned rc7. Current separate fail-closed delisting backtest remains unchanged.

### Proposed foundational slice

Branch `chatgpt/independent-ledger-kernel-20261026`. Added pure standard-library `src/lab/kernel/double_entry.py`, an exact-Decimal, canonical financial state and double-entry posting projector without any Nautilus/OMS/vendor imports. `AccountingState` carries actual cash, signed security acquisition cost, accrued claim/payable and credit-side realized earnings; `PostingBatch` enforces zero-sum and canonical account order; `transition` insists that opening capital remains unchanged. A corporate recognition cannot change actual cash. A corporate cash receipt can change **only** cash and the offsetting receivable/payable, not cost basis or realized profit. `verify_record` reconstructs every exact value and closing state SHA, preventing a merely balanced but false posting vector.

`CorporateSession` is now **schema v2** and writes the double-entry evidence **inside the same existing append-only SQLite journal row** as each domain `corporate_action` or `corporate_cash` event. Both domain state and independent postings replay from the same committed event; no second SQLite commit or two-store crash mismatch. Boot header pins the opening capital. Older v1 journals explicitly fail closed until independently migrated, no silent conversion. No broker, Nautilus account mutation or executable external adapter was introduced.

`tests/test_portable_double_entry.py` covers long and short corporate actions, deferred receipts, zero-cost-basis/zero recovery, fake cash/profit injection, reversed signs, bogus balanced journal entries, currency and precision and stdlib imports. Existing corporate journal tests now embed postings and replay them. Adversarial cases: a locally hash-chain-valid journal containing falsified but zero-sum postings **must** fail the independent economic projector, as must a v1 journal presented as v2.

### Blocking review points

1. **F1:** treat this as scoped corporate financial conservation only, not full multi-asset prime-broker accounting or corporate-action native parity. No fabricated quote or volume, no real-money capability. Existing `backtest.settle_delistings` remains fail-closed.
2. **Integrity:** inspect negative security cost basis for shorts, credited realized profit/loss, cash-vs-accrual, audit identity and immutable v2 boot. Verify no hidden double-journal commit, correct crash/replay, stale or tampered record rejection.
3. **Arch independence:** portable `python -S` and `lab.mobile check` must run without Nautilus, NumPy or pandas. Native engine remains a differential test oracle; don't remove its validated tests for an unqualified new engine.
4. **Safety:** no broker integration, no autonomous order entry and no relaxation of F0-F8/7 external release criteria. Future order lifecycle must honor pending GTC, idempotency ambiguity, broker reconciliation and paper-only gates.
5. **Build:** run Ruff check/format, portable + all hosted fast tests on 3.13 and 3.14, real-clock harness, packaging/Docker, collab. Report exact SHA and counts. At submission the latest SHA's CI is running; do **not** characterize uncompleted jobs as passed.

If the native engine supports genuine corporate settlement under a separately tested path, we can reuse it. Otherwise this source-owned kernel and broker-neutral event contract allow later independent settlement without misrepresenting ordinary exchange fills.
