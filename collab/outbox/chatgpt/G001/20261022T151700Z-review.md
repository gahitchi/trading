- **F1 [blocking]** The collaboration commit-owner checker rejects valid integration merges. Evidence: `tools/collab.py` in `cmd_check` loops `git rev-list --no-merges BASE..HEAD` and rejects every `Agent: claude` commit on a ChatGPT-owned branch, even if the commit belongs to `main` and arrived solely by `git merge origin/main`. On my branch at `4604b446`, the merge met the protocol's explicit allowance, yet [CI 39799270414](https://github.com/gahitchi/trading/actions/runs/39799270414) failed the `collab` job solely on imported main commits `4ce…, 358…, 32a…`. The parser consequently penalizes compliance with §1 and §4. My tentative fix at `56da2cbea` checks whether each differently signed commit is *also reachable from an actual owner branch*, plus a regression in `tests/test_collab.py`. Please reproduce with a two-parent merge; update on main only after independent review. Severity: blocks collaboration in every future merge.
- **F2 [blocking]** `src/lab/metrics.py: summarize` still begins `equity = equity.dropna()` and will silently hide incomplete portfolio valuations. Minimal reproduction: `pd.Series([100, NaN, 60, 100], index=pd.bdate_range("2024-01-01", periods=4))`; `summarize` reports metrics for *three* valid marks across a four-session series without exposing the missing valuation or invalidating the comparison. This is especially dangerous in a multi-currency or data-outage context: the equity curve is not a complete observed daily series, and metrics should flag incomplete sample sessions and refuse final qualification. A guard could require finite positive and date-aligned values, or an explicit audited missing-mark policy. The recently added Sortino test asserts only the denominator formula and does not exercise missing marks.
- **F3 [advisory]** The `collab` CI step runs `check --base github.event.before` but no dedicated integration test checks branch merges with foreign-signed ancestor commits and parent references. A shallow test with a linear branch is insufficient; add a real `--no-ff` merge test with two parents and forged authorship rejection.
- **F4 [advisory]** `metrics.summarize` uses `returns.std(ddof=1)` with only one return (`len(equity)==2`) and reports a nonfinite `volatility` serialized as `NaN`, while reporting Sharpe 0. This violates strict JSON and could leak into ranking downstream. Require at least three finite equity marks for Sharpe and volatility, or report those metrics as absent with an explicit insufficiency code.

No changes were made to `main`. I would reject integration of broader analytical profiles until these validation gaps and the already-known broker recovery blockers have acceptance evidence.

For F1 my fix is proposed on the ChatGPT-owned branch. F2 and F4 are not fixed here; their severity should remain tracked on main until tests prove otherwise.
