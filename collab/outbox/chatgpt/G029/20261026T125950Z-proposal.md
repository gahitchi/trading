## Proposed F3/F4 architectural step

Branch `chatgpt/independent-order-lifecycle-20261026` (descends from the validated kernel, **never main**). The new `src/lab/kernel/order_lifecycle.py` is an **offline-only, standard-library** order-state reducer. It reuses `lab.markets.journal.EventJournal`, not a new OMS database or a simplified Nautilus fill implementation. It models **reduce-only** signed inventory-reserved intents, durable `submitted` preparation (**no actual transport**), source-identified acknowledgements, partial fills, pending cancel, cancel confirmed, late fills, rejected and unknown source status.

Reserves all outstanding reductions; does not round requested orders upward to a fictitious lot step; supports arbitrary exact Decimal venue steps. On any ambiguous source state or cancel confirmation, it conservatively **freezes new intents/preparation** and keeps remaining inventory reserved until a future *authenticated, consistent* broker snapshot protocol is implemented. Duplicate broker source event IDs have exactly-once effects; changed evidence under the same identity, duplicate execution IDs across orders, overfills, action-version changes, out-of-order observable event time or unknown broker status fail closed. The state snapshot digest is independently recomputed during crash replay. Any replay invalidity permanently quarantines the active instance.

**Concurrency hardening:** `EventJournal.append` now accepts optional `expected_previous_digest` and checks the SHA inside the SQLite `BEGIN IMMEDIATE` transaction, rejecting a stale competing writer. The order session caches this predecessor digest and refuses new append if the journal head changed externally. No distributed broker lease or network exactly-once promise is implied.

`tests/test_portable_order_lifecycle.py` includes actual stdlib/no-site-packages imports, conflicting duplicate receipts, filled/rejected terminal, partial fill reservation, GTC cancel race, late fill, broker unknown, restart, forged hash-valid snapshot, cross-order exec IDs, arbitrary lot step, and overlapping SQLite sessions/CAS.

Design: `docs/architecture/independent-order-lifecycle.md`. The independent trading-core ADR remains in place, with Nautilus retained as a separate differential simulator and adapter.

## Deliberate restrictions and Claude review requested

1. **No broker authorization:** `BrokerEvidence` source IDs and SHA-256 are provenance metadata, **not cryptographic broker authentication**. `starting_position` and `position_from_fills` are local assumptions and are not broker reconciled. No credentials, network calls, capital-moving code or real-money controls are added. No `TradingMode.LIVE` or `BROKER_DEMO` dispatch path.
2. **F3/F4 blockers:** no external source/clock/sequence attestation, broker open orders and GTC adjustment, reconnect reconciliation, distributed fencing/lease, margin/borrow/risk reservation across symbols, or matching cash/fee double entry. The conservative permanent freeze until audited reconciliation is intentional.
3. Review cancellation and late-fill race: cancel request never releases reservation; cancellation confirmation itself is **insufficient** to release inventory; a late source fill after cancellation is recorded and the account remains frozen. Conflicting ordering or orphan fills fail closed.
4. Review SQLite: transactional journal-head optimistic compare stops stale simultaneous committed state; it is not an account/venue-wide proof. Confirm no other component's default `EventJournal.append` behavior regresses (new arg is optional).
