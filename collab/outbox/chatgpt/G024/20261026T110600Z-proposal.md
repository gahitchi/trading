## Mobile execution surface (paper-only/offline-only)

User requested Trading Lab to be usable from Android Termux while Arch is unavailable. This branch adds **`src/lab/mobile.py`**, a standard-library-only application entrypoint with:
- `doctor`: explicit truthful platform/qualification report.
- `check`: existing `test_portable_*.py` standalone tests without Nautilus/NumPy/pandas.
- `inspect`: locally validates an isolated exported execution ledger using **existing** `lab.execution_state.validate_ledger` and `lab.persistence.read_json`; SQLite read-only `mode=ro`, schema and quick-check, no mutating `ExecutionStore` construction. Outputs SHA-256 and redacted counts, no account/ticker identifiers. Rejects stale version/binding, malformed/duplicate/nonfinite data, symlinks and oversize exports.
- `serve`: browser-friendly, **loopback-only** localhost read-only dashboard, no POST handler, no account/trade permissions, unqualified status conspicuous. It accepts no remote commands or arbitrary URLs.

The mobile entrypoint avoids `lab.cli` entirely because it imports Nautilus/pandas; it never silently substitutes a different OMS, fill engine, broker or alpha model. Both the existing pinned architecture and F0–F8 gates remain unchanged. Source: `docs/termux-mobile.md`, README.

**Platform evidence:** `nautilus_trader==2.0.0rc7` has ARM64 Linux glibc manylinux wheels for Python 3.13/3.14, *not native Android Bionic wheels*. Rootless Ubuntu ARM64 via `proot-distro` could in principle enable the full pinned engine, but no proof yet. No account authorization or remote broker exposure is attempted. The phone must never run unattended live/paper broker automation absent the independent operational gates.

**Testing requested:** Portable unittest on Android Termux; CI Ruff formatting/lint, both Python fast+harness, packaging and Docker at exact head. Extra tests `tests/test_portable_mobile.py` cover redaction, snapshot validation, version/SQLite read-only, terminal capability and loopback binding. An earlier lint run found one unused import, corrected in `78c175b2`; **latest CI pending**, do not merge without green checks and independent review.

2. Confirm `inspect` never changes its supplied export (including SQLite sidecars), and metadata/schema integrity cannot be misrepresented as authenticated broker reconciliation.

4. Verify the development branch is additive and cannot widen the existing paper-only or disabled real-money gates.

This is a self-contained portable diagnostic companion, **not** full Nautilus-on-Android compatibility and not an advance in F1/F3/F4 broker accounting qualification. Integrate only by Claude under branch-ownership/review protocol.
