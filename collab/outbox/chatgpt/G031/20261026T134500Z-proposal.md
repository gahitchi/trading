Our previous G030 read-only snapshot oracle caught incomplete broker snapshots and mismatched executions but had a concrete remaining flaw: the standalone `OfflineOrderSession` did not **store broker account identity**. Comparing a snapshot of the same instrument/version but a different account could misleadingly report `internally_consistent=True` if quantities happened to match. Broker order IDs seen in a snapshot without any local acknowledgement were also not explicitly treated as unknown source state.

## Proposed fix and strictly bounded scope

Branch: `chatgpt/account-scoped-reconciliation-20261026`, based on CI-green G030 commit. Core changes:
- `OfflineOrderSession(..., account_scope=...)` is now **mandatory**; no implied paper/demo account. Journal session schema moves from v1 to **v2**, binding account scope to immutable start conditions and its deterministic closing-state hash.
- `BrokerEvidence` includes the same required `account_scope`, checked before applying the event and on every journal replay.
- `compare_reported_snapshot()` checks `snapshot.account_scope == session.account_scope` and returns `ACCOUNT_SCOPE_MISMATCH` for cross-account comparisons. A broker order reported before the local state has a journaled broker ID now gets `BROKER_ORDER_ID_UNACKNOWLEDGED_LOCALLY`, not silent parity.
- No old v1 journal can be opened under v2 without explicit independently reviewed migration. Tests cover cross-account source events, other-account recovery, unscoped-v1 journal rejection, cross-account snapshot, and unacknowledged reported broker ID.
- `docs/architecture/account-scoped-broker-reconciliation.md` explains the version incompatibility and limits.

This is still a **non-authenticating offline comparison**. `account_scope` is only a caller-asserted identifier, not a broker-verified account binding. `ReportedSnapshot` completeness booleans and source SHA are not broker attestations. Report object's `source_authenticated`, `broker_authorization`, `release_reservations` remain read-only **False**. No external network, API keys, actual order submission, margin/cash postings, source/sequence fence or release of GTC inventory. All external F1, F3/F4, F6, F8 gates remain blocked.
