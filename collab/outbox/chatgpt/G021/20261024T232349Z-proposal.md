# Support separate IBKR Free Trial simulated account (DUR) without weakening paper-order guards

Owner specifically clarified: their live account application is separate and pending approval. They have already created a distinct Free Trial simulation account with a separate username, and the account NUMBER on IBKR's Free Trial platform has a DUR prefix. Earlier attempts mischaracterized DUR as the username and incorrectly demanded DU. No owner-specific identifiers or credentials are committed.

IBKR official documentation says:
- Free Trial exists independently of the live-account-approval process and offers delayed platform market data, see https://www.interactivebrokers.com/en/trading/free-trial.php
- **TWS API can connect to a trial account**, but cannot receive realtime data or historical candlesticks for most instruments under trial login, see https://www.interactivebrokers.com/docs/third-party-integrations/general-third-party-frequently-asked-questions
- Standard IBKR paper accounts connected to a full account support the API with market-data limitations, see https://www.interactivebrokers.com/campus/glossary-terms/paper-trading-account/
- Pinned gnzsnz IB Gateway image supports paper mode and `READ_ONLY_API=yes`; read-only API cannot submit, modify or cancel orders, see https://github.com/gnzsnz/ib-gateway-docker

Patch on ChatGPT branch `37a0bb1dcbefea3599f87eb5ea7eb30257fb7a84`:
1. `tools/broker_setup.py` recognizes `DUR[0-9]{5,}` as a separate Free Trial trial/demo account for LOGIN ONLY. Accepts it via loopback, stores credentials privately, reports `mode=demo` and `order_setup_enabled=false` in `/status` and `/connect`. Rejects live `U…` as before.
2. `compose.gateway.demo.yml` overrides Gateway with `READ_ONLY_API=yes` and `TRADING_MODE=paper`; `start_gateway` includes that overlay *only* for DUR identities. No change to the main Gateway overlay's DU account behavior.
3. `src/lab/ui/app.js` sets `brokerReady` only if `order_setup_enabled=true`. For DUR it can save login and ask Gateway to start but MUST NOT enable the paper-trading button or inject the DUR number into the lower trading plan.
4. `src/lab/safety.py` and execution agent account checks remain **unchanged and DU-only**, independently preventing order submission even if a browser control is manipulated.
5. Expanded HTTP onboarding, read-only status, simulator account guard, secret-permissions and `docker compose config` effective-environment CI regressions. CLI and GUI documentation updated; no real user info committed.

**Limitations / release constraints**:
- A Docker container starting does NOT prove IBKR login. Actual Free Trial authentication and API data/connection tests remain required on the owner's Arch host.
- Free Trial historic candlesticks are mostly absent, so the research/strategy engine cannot produce a validated normal trading session on that account. No order submission permitted in this mode.
- Existing launcher leaves the prior localhost:8766 credential helper resident. Source updates to this helper require a restart of the old process (e.g. reboot). GUI container must be rebuilt after editing sources. Guidance added; future updater should automate safe helper process upgrades.
- Tests cannot establish what broker actually reports for a DUR account in a live API session. The read-only mode is an explicit safety posture until field-tested.
