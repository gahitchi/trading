# Field report: DUR Free Trial onboarding still refused after code was pushed

Operator confirmed their Trading Lab browser continued to show a strict DU-only login error even after DUR onboarding was implemented. Cause found in launch/update lifecycle, not account classification:

- `tools/start_app.py` started the local helper on localhost:8766 detached with no PID file; on subsequent launches it returned early if `/status` had matching installation fingerprint, **without checking helper version**.
- Rebuilding `lab` Docker image changes the GUI but does NOT update the separate host Python helper process. Conversely running `git pull` alone changes files on disk but leaves the old GUI container running. Legacy setup helper still calls strict `DU[0-9]{5,}` validation.
- A separate DU-only `Your plan` field is intentional and cannot accept DUR even after credentials are saved, because the engine's paper-account guard remains DU-only.

**Fix branch 38bf1c10271ed3b468ac357e4e90fb5b2488b154:**
1. `tools/broker_setup.py` `/status` and POST responses now report `protocol_version=2` (onboarding for Free Trial via read-only Gateway). 
2. `tools/start_app.py` verifies installation fingerprint and version. If an obsolete helper is identified on Linux, it finds ONLY same-user `/proc/<pid>/cmdline` entries exactly matching `<python> <root>/tools/broker_setup.py --root <root>`, sends SIGTERM to that exact process, confirms port release, launches current helper and verifies protocol. It never blindly kills port 8766 or any other user's process. For other platforms/unverifiable ownership, it fails closed with actionable desktop relogin message.
3. `src/lab/ui/app.js` rejects old-helper status and hides credential entry to prevent user submitting a password to a stale service; instructs operator to reopen desktop launcher.
4. Lower trading-plan field explicitly says **approved DU paper account only**. DUR Free Trial login belongs exclusively in the top Interactive Brokers setup form, and Start paper trading remains disabled for DUR.
5. A real Linux integration regression test forks a legacy protocol helper on an isolated loopback port, verifies PID+root matching, updates source on disk, performs safe replacement, tests protocol upgrade and same-version reuse.
