Credit: the fixed resource route table, origin+token-checked POST controls, CSP, local fonts/icons, cautious startup interlock, and explicit in-page exit confirmation are improvements. No findings below authorize live-money trading.

- **F1 [blocking] The autonomous control panel does not display *actual* portfolio risk or even portfolio equity, so the operator cannot recognize an exposure breach from the UI.** `src/lab/agents/execution.py::_write_heartbeat` emits `cash`, raw share counts and order count but no mark-to-market equity, gross/net exposure, short gross, per-name weight, margin utilization, recent realized breach, or current configured hard ceilings. `src/lab/ui/app.js::positions` displays only Stock/Side/Shares and `render` reports cash. With the G013 financing-drift example (actual gross 1.524x against 1.50x), the page can show a green 'Your plan is active' with no direct exposure warning. This is a **release/operator-visibility blocker**, not a claim that the new UI changed the underlying execution risk: publish independently validated current risk state from the engine, distinguish stale/unknown marks, surface hard breaches and blocks prominently, and test the display with synthetic over-cap/unknown-mark heartbeats. Do not calculate authoritative broker risk solely from browser-side shares.
- **F2 [advisory, release-critical UX] Emergency exit becomes unavailable precisely when the engine has crashed or is disconnected.** `src/lab/ui/app.js::render` sets `exit.disabled = busy || !state.engine_alive`; however the broker may still hold positions after an app/engine crash, and `Controller.status` retains the last positions without an actionable recovery path in the panel. Preserve the prohibition on trading without reconciliation, but give the user a visible 'engine down, broker positions may remain' alarm and guided safe recovery / persistent flatten-intent workflow; never silently imply positions are flat. Include a crash-with-open-positions acceptance scenario.
- **F3 [advisory, product completeness] C005-F6 and F7 remain unresolved after the UI rewrite.** `src/lab/app.py::STRATEGIES` only permits `sma_trend`, `rsi_reversion` or both; `Controller.configure` forces `speed="daily"`; `src/lab/ui/index.html` exposes neither advanced intraday modes nor validated strategy bank/weighting. `lab.universe.equity` is still US stocks only. Do not advertise an FX/crypto or advanced multi-speed one-click implementation yet; make supported scope visible and offer opt-in *reviewed* strategies rather than silently enabling risky behaviors.
- **F4 [advisory] The front-end behavior and Windows launch are not release-qualified by existing automated checks.** `tests/test_app.py` checks served asset references and HTTP security; `tests/test_app_installer.py` mocks PowerShell shortcuts and the chosen browser. There is no automated test asserting DOM rendering, risk label correctness, approval confirmation, keyboard/navigation accessibility, or control state over transitions. Require a real Windows Docker/shortcut smoke run and scripted Chromium UI control-flow smoke runs before calling the launcher plug-and-play. `tools/start_app.py::open_app` also does not fall back to another browser if launching the first installed executable raises `OSError`.
- **F5 [advisory, release gate] The shipping product still requires externally verified broker behavior.** `docs/release-criteria.json` continues to mark code review, broker lifecycle, statistical calibration, market data/execution, adaptive policy, operations and security as `blocked`. Green CI cannot close B07 or the other physical IBKR/power-loss/qualification criteria.
