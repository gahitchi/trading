I cannot claim a full pytest/ruff run in this environment; findings below are code-path reproductions, not release qualification.

- **F1 [blocking] `value_area` selects the wrong direction after alternating failed excursions.** In `ValueAreaReversion.target`, `before=closes[:-confirm]` and `np.any(before < val)` take precedence over `np.any(before > vah)`, regardless of which excursion happened last. Reproduce using the existing `tests/test_intraday.py::_two_sessions` previous-session profile and today's closes `[99.0, 102.0, 100.5, 100.6]` with `confirm=2`. The profile is approximately VAL=99.84, VAH=100.94: the latest failed auction is **above** (102.0), yet the strategy returns **long +1.0** because it also saw 99.0 earlier. Expected: most recent pre-confirmation outside excursion determines direction (short, if enabled), or ambiguous sequences abstain. Preserve a regression that fails on this commit.
- **F2 [blocking] Valid zero-range bars can lose all their volume in the profile.** In `value_area`, `searchsorted(..., side="right") - 1` for the low, but `searchsorted(..., side="left") - 1` for the high, yields `a>b` when `high==low` precisely on an internal bin boundary; `v/(b-a+1)` divides by zero and `profile[a:b+1]` is empty. Reproduce `value_area(high=np.array([20.,15.]), low=np.array([10.,15.]), volume=np.array([1.,100.]), bins=10)`: the 100-volume print at 15 is omitted; summed histogram volume is 1 instead of 101 (NumPy divide warning, or `FloatingPointError` with `np.seterr(divide="raise")`). Assign a zero-range print to one bin and pin histogram conservation of volume before trusting this technique.
- **F3 [blocking] The deployment checker can return PASS without inspecting deployed published ports.** `run()` scans only `root.glob("*compose*.yml")`, missing supported `compose.yaml` and `docker-compose.override.yaml` files. `_published()` recognizes only block-form `ports:\n - "..."` and silently skips valid inline YAML `ports: ["0.0.0.0:8765:8765"]`. These let Docker publish a public trading/setup port while the checker checks nothing, contrary to the stated all-ports assertion. Reproduce in a fixture with a safe `docker-compose.yml` plus a `compose.override.yaml` exporting 8765 publicly, or a single `compose.yaml`. Use rendered `docker compose config --format json` (and reject unavailable/non-zero render) rather than incomplete text parsing; check the actual deployed containers, too.
- **F4 [blocking] The stated 20-return warmup is not enforced for risk-based sizing.** `AllocatorAgent.weights()` passes `min(20, self.config.vol_window)`; `config.py` permits `vol_window>=2`. Selecting `weighting="hrp"` and `vol_window=2` therefore activates covariance-based allocations on **two** shared returns despite C005's explicit "equal weights until 20 shared returns" promise. Either require `vol_window>=20` for `hrp`/`inverse_vol`, or always demand 20 and remain equal for smaller windows; test at window 2, 19, 20.
- **F5 [advisory]** Update `src/lab/default.toml`'s intraday technique list to include `value_area`, and document that bar-based volume-at-price is an approximation (already acknowledged in C005).

**Weighting question:** `normalize_active=false` keeping inactive sleeves' shares in cash is consistent with the existing fixed-budget behavior; `normalize_active=true` redistributing group capital only to active sleeves is appropriate, as long as the UI makes this distinction explicit. No objection to the choice; acceptance is conditional on F4 being corrected.
