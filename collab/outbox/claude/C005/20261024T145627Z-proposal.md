Gabriel asked me to add the useful upgrades from a set of trading/AI tooling ideas he had collected. I
added four and rejected the rest earlier (recorded in his notes, not here). This was my turn; please review
it in yours.

1. **`AGENTS.md`, read by `CLAUDE.md`: working rules for both of us.**
   - Think before writing (state assumptions, ask when a request reads two ways).
   - The simplest change that meets the goal; no speculative options.
   - Surgical diffs.
   - Verify against the goal (reproduce, then fix, keeping the reproduction as a test).
   - Say what wasn't done; missing evidence is "blocked".

   It also restates the project rules (paper only, branches, no secrets or raw evidence, no look-ahead, the
   hand-off checks). Object to anything you think is wrong or missing. It binds us both.
2. **Risk-based capital sharing: `[portfolio] weighting = equal | inverse_vol | hrp`** (`lab.allocation`,
   AllocatorAgent).
   - Point in time: only closes the allocator has seen, returns only on intervals every stock shares at both
     ends, and equal weights until 20 shared returns exist.
   - HRP splits along the dendrogram's own clusters (single linkage), not by halving the ordered list. With
     the original halving, two near-identical stocks plus an independent one came out at about a third each
     (my first version). The test pins the cluster split: the twins share one half.
   - numpy only. skfolio's scikit-learn/cvxpy dependency graph isn't worth it in the hash-locked build for
     two methods.
   - The default stays `equal`, so behaviour is unchanged.
   - Tests: unit cases, and a backtest where inverse volatility holds well over twice the calm-to-wild ratio
     that equal weights hold.

   Challenge: the weights renormalize over the active members only when `normalize_active` is set. Otherwise
   all members share the budget. Is that what you would expect?
3. **`value_area`: a built-in intraday technique.**
   - It builds the previous session's volume profile from bars (each bar's volume spread evenly over its
     range), with the point of control and the 70% value area.
   - Failed auction / "80% rule": outside the value area, then `confirm` closes back inside, means going for
     the opposite edge. The stop is a close back outside on the side it came from. One trade per session.
   - Unit tests, plus a run through the agents at 5m.

   Known limit: a profile approximated from 5–15 minute bars is coarse. Real volume-at-price would need
   tick data.
4. **`tools/deployment_check.py`**, plus a pre-cloud checklist in RUNBOOK §2. The tool checks:
   - published ports are on 127.0.0.1;
   - the password file exists and has mode 600;
   - `.env` and `secrets/` are untracked and git-ignored;
   - a `DU` paper account and no live port;
   - a Telegram warning when alerts aren't set;
   - on Linux, no public listener on a trading port.

   The checklist adds an external `nmap` from another machine and an independent AI penetration test (Strix)
   before the server is left alone. It's a checklist, not a pentest, and it says so.

Not done: none of this is validated on real data. The weighting needs a `lab backtest` comparison on a real
universe on Gabriel's machine. I can't fetch Yahoo data from my environment. `value_area` needs the intraday
history to accumulate first. All of it stays a hypothesis until it passes the protocol.
