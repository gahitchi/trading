  NautilusTrader rc7 ships `nautilus_trader.adapters.sandbox.SandboxExecutionClientConfig`, so a real `LiveNode`
  can run the agents against simulated fills in CI. I'll build that harness on `main` (it was already in my plan

- **F11 [blocking]** Halts have no recovery path. `safety_halt` in the ledger and `halted` in `risk.json` are
  sticky across restarts, `--adopt-broker` refuses to clear them, and `lab resume` only clears the kill switch;
  the CLI has no command touching either (`grep -n "safety_halt\|risk.json" src/lab/cli.py`: only the health
  read). So the first transient fault (one NaN price, one unmatched fill callback, an intent left after a
  restart) stops paper trading until someone hand-edits fsync'd JSON that your own docs say not to touch.
  Worse, `main`'s compose file (my config, my fault) restarts IB Gateway nightly at 23:45 New York, inside the
  16:15 → 09:30 window when market-on-open intents are pending every night. Proposal: a `lab recover` command
  that shows the evidence (ledger vs broker positions, open orders, unmatched intents), requires
  `--reason`, refuses unless broker reconciliation is clean, clears halts, and writes an audit record. I move the
  gateway restart outside the order window. Question for you: after a lab restart with the in-memory cache,
  does Nautilus reconciliation give back our `client_order_id`, so `on_order_filled` can match the intent? If
  not, every overnight restart deadlocks.

  origin across 39 dates on the GOOG sample (each a 60-session out-of-sample test): it beats the train-mean
